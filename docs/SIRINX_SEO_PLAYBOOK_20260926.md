## Part 1: กฎของ Google ที่ตัดสินทุกอย่าง

ก่อนพูดถึงเทคนิค ต้องเข้าใจกฎก่อน เพราะกฎนี้เป็นตัวตัดสินว่าแผนเนื้อหาแบบไหนอยู่รอด
คำนิยามด้านล่างเป็นถ้อยคำจากเอกสารทางการของ Google

### 1.1 Doorway abuse (การใช้หน้าประตู)

> "Having multiple domain names or pages targeted at specific regions or cities that funnel users to one page"
> "Creating substantially similar pages that are closer to search results than a clearly defined, browseable hierarchy"

นี่คือนิยามที่ตรงกับหน้า province ของ SIRINX **เป๊ะ** ในสองจุด

**จุดที่ 1: "substantially similar pages"**
ผมวัดแล้วได้ 0.883 (5-gram Jaccard) ระหว่างหน้า province ทุกคู่ที่สุ่มมา 28 คู่
คือเนื้อหา 88% เหมือนกัน ต่างกันแค่ชื่อจังหวัด

**จุดที่ 2: "closer to search results than a clearly defined, browseable hierarchy"**
77 หน้าที่แยกจากกันแทนที่จะเป็นโครงสร้างที่ผู้ใช้เดินได้ เป็นการยกหน้าเข้าเขตผลลัพธ์โดยตรง
ก่อนที่ผู้ใช้จะเจอหน้าหลัก `/solar-carport` หรือ `/`

**นี่ไม่ใช่ความเสี่ยงเชิงทฤษฎี** คือนิยามที่เขียนตรง ๆ ว่าอะไรถือว่าผิด

### 1.2 Scaled content abuse (การผลิตเนื้อหาในจำนวนมาก)

> "Using generative AI tools or other similar tools to generate many pages without adding value for users"
> "Creating many pages where the content makes little or no sense to a reader but contains search keywords"

นี่คือคำตอบตรง ๆ สำหรับคำขอ "เขียนเนื้อหา 3,000-12,000 คำ ลงในเว็บ ให้ครอบทุกคีย์เวิร์ด"
การผลิตเนื้อหา 77 จังหวัด × 10,000 คำ ด้วย AI โดยไม่มีข้อมูลเฉพาะท้องถิ่น
คือรูปแบบที่นิยามนี้ระบุตรง ๆ

ข้อสรุปสำคัญ: **ปริมาณคำไม่ใช่ตัวตัดสิน** ตัวตัดสินคือ "add value for users"
หน้า 500 คำที่มีข้อมูลจริงเฉพาะจังหวัด มีค่ามากกว่าหน้า 12,000 คำที่เหมือนกันทุกจังหวัด

### 1.3 Keyword stuffing

> "Blocks of text that list cities and regions that a web page is trying to rank for"

ข้อความนี้ตรงกับหน้า `/provinces` ที่ผมเพิ่งสร้าง ซึ่งเป็นรายชื่อ 77 จังหวัด
**ข้อแก้**: หน้านี้ต้องเป็น *ด่านนำทาง* (navigation hub) ที่มีคำอธิบายสั้น ๆ ว่าทำไมถึงต้องเลือกจังหวัด
ไม่ใช่หน้าที่พยายามจับอันดับ "โซลาร์เซลล์ กรุงเทพ" ทั้ง 77 คำในหน้าเดียว
ถ้าทำผิดจะกลายเป็น keyword stuffing ซึ่งอยู่ในรายการเดียวกับ doorway abuse

### 1.4 Link spam และลิงก์ที่ผ่านการรับรอง (qualified links)

> "Buying or selling links for ranking purposes"
> "Low-quality directory or bookmark site links"
> "Exchanging goods or services for links"
> "Advertorials or native advertising where payment is received for articles that include links that pass ranking credit"

แต่มีข้อยกเว้นสำคัญ:

> "Google does understand that buying and selling links is a normal part of the economy of the web for advertising and sponsorship purposes. It's not a violation of their policies as long as those links are qualified with a rel="nofollow" or rel="sponsored" attribute"

**ความหมายที่ใช้ได้จริง**:
- ซื้อลิงก์เพื่ออันดับ = ผิดกฎ
- ซื้อโฆษณา/สปอนเซอร์ที่มีลิงก์ = ไม่ผิด ถ้าใส่ `rel="sponsored"`
- ลิงก์จากไดเรกทอรีคุณภาพต่ำ = ผิดกฎ
- แลกเปลี่ยนสินค้า/บริการเพื่อขอลิงก์ = ผิดกฎ

### 1.5 Site reputation policy (อัปเดต 2026-08-28)

นโยบายใหม่ที่โฟกัสเนื้อหาบุคคลที่สามที่ถูกเผยแพร่บนเว็บของคุณ
เพราะหน้านั้นมีสัญญาณความน่าเชื่อถือที่คุณสร้างเอง

**ความหมายที่ใช้ได้จริง**: การเอาบทความของที่อื่นมาลงบนเว็บเรา
เพื่อให้ได้อันดับจากความน่าเชื่อถือของโดเมนเรา = ผิดกฎ
Google จะตรวจ 4 อย่าง: การนำเสนอ/ดีไซน์, คุณภาพเทียบกับส่วนอื่นของเว็บ, การระบุผู้เขียน/ผู้รับผิดชอบ,
และว่าเนื้อหานั้นปรากฏที่อื่นในรูปแบบเดียวกันหรือใกล้เคียงกันหรือไม่

ข้อสรุป: **อย่าเอาบทความมาลง** ถ้าจะทำ ให้บรรณาธิการตรวจและระบุชัดว่าใครเขียน

### 1.6 บทสรุป Part 1

| แผน | สถานะตามนิยามทางการ |
| --- | --- |
| เขียน 10,000 คำ × 77 จังหวัดด้วย AI | ❌ scaled content abuse |
| ปล่อยให้ 77 หน้าคงซ้ำ 88% | ❌ doorway abuse |
| หน้า 77 จังหวัดที่มีข้อมูลเฉพาะจังหวัดจริง + โครงสร้างที่เดินได้ | ✅ ทางที่ถูกต้อง |
| ซื้อลิงก์เพื่ออันดับ | ❌ link spam |
| ซื้อสปอนเซอร์ + `rel="sponsored"` | ✅ อนุญาต |
| เอาบทความคนอื่นมาลงเร็ว ๆ | ❌ site reputation |

## Part 2: SIRINX อยู่ตรงไหนตอนนี้ (วัดจริง)

จาก `docs/SEO_AEO_AUDIT_20260925.md` ผลตรวจ 16 ข้อ: **7 PASS, 8 FAIL, 1 ไม่ได้ลอง**

### แก้แล้ว (วัดบน local build แล้ว ยังไม่ deploy)

| ข้อ | ผล |
| --- | --- |
| `FAQPage` ซ้ำ 2 ชุด | เหลือ **1 ชุด** (8 คำถาม) |
| breadcrumb schema ไม่มีของให้เห็น | เพิ่ม **visible breadcrumb** |
| หน้า province เป็น orphan | เพิ่ม **/provinces** มี 77 ลิงก์ + ลิงก์กลับ |
| `lang="th"` ไม่ตรงกับ JSON-LD | เปลี่ยนเป็น **`th-TH`** + hreflang |
| sitemap ไม่มี hub | **96 URLs** มี `/provinces` |
| served HTML ของ hub ว่าง | **static shell** มี 77 ลิงก์ |
| FAQ schema เพี้ยนจากเนื้อหาจริง | เทสต์กันครบ 77 จังหวัด × 3 ภาษา |
| **เนื้อหาซ้ำ** | **0.912 → 0.883 → 0.829** (ดูรายละเอียดล่าง) |

### ความซ้ำลดลงจริง และวัดทีละชั้น

| ชั้นที่เพิ่ม | similarity (5-gram Jaccard) | หลักฐาน |
| --- | --- | --- |
| เริ่มต้น | **0.912** | 28 คู่ ไม่มี spread |
| + FAQ เฉพาะจังหวัด 2 ข้อ | **0.883** | ลด 0.029 |
| + ข้อมูลพลังงานจริงจาก PVGIS (ครบ 77 จังหวัด) | **0.829 - 0.847** | ลด 0.054 อีก วัด 55 คู่จาก 11 จังหวัด |

ยังสูงกว่าเกณฑ์ที่ตั้งไว้ (0.6) แต่ **ทิศทางถูกแล้ว และทุกจุดที่ลดลงมามาจากข้อมูลจริงที่มีแหล่งอ้างอิง**
ไม่ใช่การเขียนคำเพิ่ม

### ข้อมูลจริงที่ใส่แล้ว: พลังงานแสงอาทิตย์รายจังหวัด

แหล่ง: **PVGIS v5.3, European Commission Joint Research Centre** (ฐานข้อมูล PVGIS-ERA5, ช่วงปี 2005-2023)
ไฟล์: `shared/provinceEnergyData.ts` (สร้างจาก `docs/seo/generate-province-energy-data.mjs`)

ค่าที่ได้ **ต่างกันจริง** ไม่ใช่ค่าเดียวกันทั้ง 77 จังหวัด:

| | ค่าการแผ่รังสี (kWh/m²/วัน) | ผลผลิตต่อหน่วยกำลัง (kWh/kWp/ปี) |
| --- | --- | --- |
| ต่ำสุดที่มีข้อมูล | น่าน **4.78** | |
| สูงสุดที่มีข้อมูล | ประจวบคีรีขันธ์ **5.34** | |
| กรุงเทพฯ | 5.12 | 1,401 |
| เชียงใหม่ | 4.84 | 1,302 |

หน้า province จะแสดงบล็อกนี้ **เฉพาะจังหวัดที่มีข้อมูลเท่านั้น**
จังหวัดที่ยังไม่มีข้อมูลจะไม่แสดงเลย ไม่ใช่แสดงตัวเลขเดา
และทุกบรรทัดมีคำอธิบายว่าเป็นค่ากลางทางภูมิอากาศ ไม่ใช่ผลสำรวจ ไม่ใช่การรับประกัน

### ข้อมูลที่พยายามแล้วแต่ **ใช้ไม่ได้**: รายชื่ออำเภอจาก Wikidata

ดึงรายชื่ออำเภอ (amphoe) จาก Wikidata SPARQL ได้ 76 จังหวัด / 878 อำเภอ
แต่ **เทสต์ตรวจจับว่าข้อมูลไม่ถูกต้อง** จึงถอดออกจากเว็บและลบไฟล์ข้อมูลทิ้งแล้ว

ผลเทียบกับจำนวนอำเภอที่เป็นข้อเท็จจริง:

| จังหวัด | Wikidata ให้ | จริง | ผล |
| --- | --- | --- | --- |
| พิษณุโลก | 9 | 9 | ตรง |
| เชียงใหม่ | 25 | 25 | ตรง |
| นครราชสีมา | 32 | 32 | ตรง |
| ภูเก็ต | 3 | 3 | ตรง |
| **สมุทรปราการ** | **6** | **32** | **ผิด ขาด 26 อำเภอ** |
| **ชลบุรี** | **11** | **8** | **ผิด เกิน 3** |
| **ขอนแก่น** | **26** | **23** | **ผิด เกิน 3** |

ยอดรวม 878 ตรงกับตัวเลขที่คาดไว้ ทำให้ **ตรวจจับได้ยากถ้าดูแค่ยอดรวม**
แต่รายจังหวัดผิดจริง ถ้าเอาไปเขียนว่า “สมุทรปราการ 6 อำเภอ” บนเว็บบริษัท จะเป็นข้อเท็จจริงที่ผิด
ซึ่งแย่กว่าไม่มีข้อมูลเลย

**ข้อสรุป**: ต้องใช้แหล่งจากกรมการปกครองส่วนภูมิภาค หรือท้าวอำนาจจังหวัดโดยตรง
Wikidata ใช้ได้กับข้อมูลอื่น (พิกัดจังหวัดใช้ได้ เพราะเป็นพิกัดที่มีคนยืนยันและตรวจสอบย้อนหลังได้)
แต่ **จำนวนและรายชื่อหน่วยย่อยการปกครองใช้ไม่ได้**

บทเรียน: เทสต์ที่เขียนเพื่อ spot-check ค่าที่รู้จริง เป็นตัวที่จับปัญหานี้ได้
ถ้าไม่มีเทสต์นี้ ข้อมูลผิดจะได้ขึ้นเว็บและไม่มีใครรู้จนกว่าลูกค้าจะทักมาถาม

| ข้อ | สถานะ | ทำไม |
| --- | --- | --- |
| เนื้อหาซ้ำ 83% | 0.883 → **0.829** | ต้องมีข้อมูลเฉพาะจังหวัดเพิ่ม (อำเภอ, PEA/MEA, อุตสาหกรรม) |
| รายชื่ออำเภอ | **ปฏิเสธแล้ว** | Wikidata ให้จำนวนผิด 3 จังหวัด ต้องใช้แหล่งกรมการปกครอง |
| `/projects/*` ไม่อยู่ใน sitemap | 0 รายการ | ทั้ง 2 โครงการยังไม่ผ่าน evidence gate ของตัวเอง |
| region ขัดกัน 5 จังหวัด | ยังไม่แก้ | ต้องมีแหล่งอ้างอิง DOPA |
| วัดผลไม่ได้เลย | ไม่มี GSC/GA4 | ต้องเชื่อมต่อ |

## Part 3: Keyword map 1,712 แถว ใช้ยังไง

ไฟล์: `docs/seo/keyword-map-77-provinces.csv`
โครงสร้าง: 18 national + 22 pattern × 77 จังหวัด = 1,712 แถว
ทุกแถวมี `volume_status = unmeasured` เพราะไม่มีเครื่องมือวัด

### 5 ชั้น และหน้าที่ควรเป็นเจ้าของ

| ชั้น | จำนวน | Intent | หน้าเจ้าของ | หมายเหตุ |
| --- | --- | --- | --- | --- |
| L0 national | 18 | ผสม | `/`, `/solar-carport`, `/solutions`, `/industries`, `/investment`, `/pricing`, `/home-solution` | **ต้นทุนต่ำที่สุด** เพราะมีเนื้อหาจริงอยู่แล้ว |
| L1 province core | 385 | commercial | `/solar-carport/<slug>` | หน้าที่มีอยู่ ต้องแก้ความซ้ำ |
| L2 price/commercial | 462 | transactional | cluster หน้า | ต้องมีหลักฐาน หรือใช้ถ้อยคำ "ประเมินหลังสำรวจ" |
| L3 cluster | 231 | commercial | `/solar-carport/<slug>/{ev,bess,factory,hotel}` | ยังไม่มีจริง |
| L4 AEO questions | 616 | informational | FAQ + schema | **คือชั้นที่ตอบได้วันนี้** |

### กฎการใช้

1. **หนึ่ง intent ต่อหนึ่งหน้า** ไม่ต้องพยายามให้หน้าเดียวชนะทุกคำในชั้นเดียวกัน
2. **L4 ตอบได้ทันที** เพราะเป็นคำถามเกี่ยวกับกระบวนการ ไม่ต้องมีตัวเลขราคา
3. **L2 ห้ามเขียนตัวเลข** จนกว่าจะมีใบเสนอราคาที่ลงนามแล้ว
4. **volume_status ยังเป็น unmeasured ทั้งหมด** ลำดับความสำคัญจริงต้องรอ GSC

### 4.2 ข้อมูลเฉพาะจังหวัดที่ใช้ได้จริง

นี่คือหัวใจของ Part นี้ ข้อมูลที่**ห้ามเขียน**ถ้าไม่มีแหล่งอ้างอิง และ**ต้อง**มีถ้าจะแยกหน้า

| ข้อมูล | เขียนได้ | แหล่งอ้างอิง | หมายเหตุ |
| --- | --- | --- | --- |

### 5.2 `lastmod`

สองแบบที่ผิดทั้งคู่:
- live ไม่มีเลย → crawler เดาเอง
- build ใส่เวลาที่ build → crawler เรียนรู้ว่าฟิลด์นี้ไม่มีความหมาย แล้วเลิกสนใจ

**แก้**: เก็บ `lastmod` ต่อ route จากวันที่ content เปลี่ยนจริง หรือ **ตัดออกเลย** ถ้ายังไม่มีระบบติดตาม

### 5.3 served HTML ของหน้า province

นี่คือปัญหาที่กระทบ AI crawler มากที่สุด เพราะ crawler ส่วนใหญ่ไม่รัน JavaScript
กลไกมีอยู่แล้ว (`SIRINX_STATIC_PROVINCE_CANARY`) แต่ถูกปิดไว้
เมื่อเปิด ต้องเขียนเนื้อหา province ลง shell ก่อน ไม่ใช่แค่เปิดสวิตช์
มิฉะนั้นจะเป็นการส่งเนื้อหาต่างจากที่ผู้ใช้เห็น ซึ่งเสี่ยงเข้าข่าย **cloaking** ตามนิยามใน Part 1

## Part 6: AEO (Answer Engine Optimization)

AEO = ทำให้ระบบตอบคำถาม (Google AI Overviews, ChatGPT, Perplexity, Copilot) อ้างอิงเว็บเรา

### 6.1 สิ่งที่ต้องเป็นจริงก่อน

| ข้อกำหนด | SIRINX ตอนนี้ |
| --- | --- |
| เนื้อหาต้องอยู่ใน HTML ที่เสิร์ฟ (ไม่ต้องรัน JS) | ❌ หน้า province ว่าง |
| คำตอบต้องตรงประเด็นในไม่กี่ประโยคแรก | ⚠️ มีแต่ทั่วไป |
| ต้องมี schema ที่ถูกต้องและไม่ซ้ำซ้อน | ✅ แก้แล้ว |
| ต้องมีแหล่งอ้างอิงที่ตรวจสอบได้ | ❌ ยังไม่มี province data |
| ต้องเข้าถึงได้ผ่าน robots.txt ของ AI crawler | ⚠️ ยังไม่ได้ตรวจ |

### 6.2 8 คำถาม L4 ที่ตอบได้วันนี้

จาก keyword map ชั้น L4 มี 8 pattern แต่ตอบได้จริง 5 ตอนนี้

**ตอบได้** (เป็นเรื่องกระบวนการ ไม่ต้องมีตัวเลข)
1. `Solar Carport ใน{P} ต่างจาก Solar Rooftop อย่างไร` ✅ เขียนแล้ว
2. `ขั้นตอนติดตั้ง Solar Carport` ✅ เขียนแล้ว
3. `ต้องขออนุญาตอะไรบ้าง` ✅ เขียนแล้ว
4. `มีรูปแบบการลงทุนอะไรบ้าง` ✅ เขียนแล้ว
5. `หลังติดตั้งแล้วดูแลอย่างไร` ✅ เขียนแล้ว
6. `ประเมิน Solar Carport ใน{P} ต้องใช้ข้อมูลอะไร` ✅ เพิ่งเพิ่ม
7. `พื้นที่แบบใดใน{P} ควรเริ่มประเมิน` ✅ เพิ่งเพิ่ม

**ตอบไม่ได้** (ต้องมีหลักฐานก่อน)
8. `โซลาร์เซลล์{P} คืนทุนกี่ปี` → ต้องมีข้อมูลจริงจากโครงการ
9. `บริษัทโซลาร์เซลล์{P} ที่ไหนดี` → ต้องมีรีวิวจริง
10. `ระบบไฟฟ้า {P} เป็น PEA หรือ MEA` → ต้องมีแหล่งอ้างอิง

**รูปแบบคำตอบที่ AI engine ชอบ**: ประโยคตอบตรงประเด็นก่อน แล้วค่อยอธิบาย
ห้ามเริ่มด้วย "ในปัจจุบันพลังงาน..." แล้วค่อยมาบอกคำตอบท้าย ๆ

### 6.3 robots.txt ของ AI crawler

ต้องตรวจและตัดสินใจอย่างชัดเจนว่าจะเปิดหรือปิด GPTBot, PerplexityBot, ClaudeBot
ถ้าปิด ก็เป็นการตัดความสามารถในการถูกอ้างอิงออกไปเลย
ข้อเสนอ: **เปิด** เพราะเราไม่มีเนื้อหาที่ต้องปกป้อง และการถูกอ้างอิงคือช่องทางการตลาด
แต่ต้องตัดสิ้นใจอย่างตั้งใจ ไม่ใช่ปล่อย default

## Part 7: GEO (Generative Engine Optimization)

GEO เน้นการถูก *อ้างอิง* ในคำตอบของ AI ไม่ใช่แค่ถูกจัดอันดับ

### 7.1 ต่างจาก SEO ยังไง

| มิติ | SEO | AEO / GEO |
| --- | --- | --- |
| สิ่งที่วัด | อันดับ, CTR | ถูกอ้างอิงหรือไม่, ใครถูกอ้าง |
| รูปแบบเนื้อหา | ยาวได้ | ตอบได้เฉพาะกิ่ง |
| โครงสร้าง | H1/H2 | entity + ความสัมพันธ์ + ข้อเท็จจริงที่ตรวจสอบ |
| ลิงก์ | authority signal | ต้องเป็นแหล่งที่ AI ไว้ใจ |

### 7.2 สิ่งที่ช่วย SIRINX ได้จริง

1. **entity ชัดเจน**: `Organization` + `Service` + `areaServed` ต่อจังหวัด → มีอยู่แล้ว
2. **ข้อเท็จจริงที่ตรวจสอบได้**: PEA/MEA, ขั้นตอนอนุญาต, ข้อมูลแสงแดดพร้อมแหล่งอ้างอิง → ยังไม่มี
3. **ความสอดคล้องของข้อมูล**: schema ต้องตรงกับข้อความที่มองเห็น → เพิ่งทำแล้ว + มีเทสต์กัน
4. **เนื้อหาใน HTML**: AI crawler ไม่รัน JS → ยังขาด

### 7.3 เรื่อง `llms.txt`

มีการเสนอไฟล์ `llms.txt` สำหรับชี้ทางให้ LLM ใช้ แต่ยังไม่มีการยืนยันจากผู้ให้บริการ AI รายใหญ่
ว่ารองรับจริง ผมจึง **ไม่แนะนำให้ลงทุนเวลาตอนนี้** เพราะยังไม่มีหลักฐานว่าได้ผล
ถ้าจะทำ ทำเป็นไฟล์เล็ก ๆ ที่ระบุหน้าหลักและหน้า province hub เท่านั้น ไม่ต้อง invest มาก

## Part 8: Backlinks

### 8.1 กฎที่ใช้ได้จริง (อ้างอิง Part 1.4)

| วิธี | สถานะ | เงื่อนไข |
| --- | --- | --- |
| ซื้อลิงก์เพื่ออันดับ | ❌ ผิดกฎ | link spam |
| ซื้อโฆษณา/สปอนเซอร์ | ✅ | ต้อง `rel="sponsored"` |
| แลกเปลี่ยนสินค้าเพื่อขอลิงก์ | ❌ ผิดกฎ | |
| ลิงก์แลกกัน (link farm) | ❌ ผิดกฎ | |
| ไดเรกทอรีคุณภาพต่ำ | ❌ ผิดกฎ | |
| บทความที่มีลิงก์ซำ ๆ | ❌ | ข้อความไม่ใช่ลิงก์ |
| guest post ที่ตีกรอบ | ⚠️ อยู่ในเขตแดง | ถ้าจ่ายเงินต้อง nofollow |
| รีวิวจากสื่อ/อุตสาหกรรม | ✅ | earned media |
| ข้อมูลที่มีคนอ้างอิงจริง | ✅ | ดีที่สุด |

### 8.2 ช่องทางที่เหมาะกับ SIRINX

เรียงตามความสมจริง ไม่ใช่ตามความหวัง

**ระดับ 1: ทำได้เอง ไม่ต้องขอใคร**
- ข้อมูลเฉพาะจังหวัดที่มีแหล่งอ้างอิง (PEA/MEA, ขั้นตอน, แสงแดด) → เป็นสิ่งที่คู่แข่งอ้างอิงได้
- case study ที่ผ่าน evidence gate แล้ว (HOLATEL) → มีอยู่ 1 เคส
- เครื่องมือคำนวณ ROI ที่ใช้ได้จริง → link ได้จากบทความเทคนิค

**ระดับ 2: ต้องมีของจริงก่อน**
- ติดตั้งเสร็จเพิ่ม → commissioning record → ขอรีวิวจริง
- เคสฐาน EEC / นิคมฯ → กรณีศึกษาเฉพาะกลุ่มอุตสาหกรรม

**ระดับ 3: ต้องจ่ายเงิน**
- สปอนเซอร์บทความในสื่ออุตสาหกรรม → `rel="sponsored"`
- ประกาศบนไดเรกทอรีธุรกิจที่มีมาตรฐาน (DBD, หอการค้า) → ไม่ต้องซื้อลิงก์ คือข้อมูลที่ถูกต้อง

### 8.3 สิ่งที่ไม่ต้องทำ

- ไม่ต้องซื้อลิงก์จากตลาดลิงก์ ไม่ว่าราคาเท่าไหร่
- ไม่ต้องทำ PBN (private blog network)
- ไม่ต้องทำลิงก์แมสซิฟ
- ถ้าจะจ่ายเงินเพื่อโฆษณา ให้ใส่ `rel="sponsored"` เสมอ ตาม Part 1.4

### 8.4 สิ่งที่ยังทำไม่ได้

ผมไม่มี Ahrefs/Majestic/SEMrush จึงวิเคราะห์ backlink profile ของ SIRINX และคู่แข่งไม่ได้
ถ้าจะทำ ต้องต่อเครื่องมือก่อน หรือใช้ GSC Links report (ฟรี) เป็นจุดเริ่มต้น

Name, Address, Phone ต้องตรงกันทุกที่ที่ปรากฏ

## Part 10: รูปแบบที่จะทำให้เสียอันดับ

รวบรวมจาก Part 1 เป็น checklist

- [ ] ผลิตหน้าเป็นจำนวนมากโดยไม่มีคุณค่าเพิ่ม (scaled content abuse)
- [ ] หน้าจำนวนมากที่เนื้อหาเกือบเหมือนกัน (doorway abuse)
- [ ] มีระดับที่ชัดเจนกว่าโครงสร้างที่ผู้ใช้เดินได้
- [ ] บล็อกข้อความรายชื่อเมือง/จังหวัดในหน้าเดียว (keyword stuffing)
- [ ] ซื้อลิงก์เพื่ออันดับ
- [ ] โฆษณาที่จ่ายเงินแล้วไม่ใส่ `rel="sponsored"`
- [ ] เอาบทความคนอื่นมาลงเร็ว ๆ โดยไม่มีบรรณาธิการ
- [ ] ส่งเนื้อหาต่างจากที่ผู้ใช้เห็นเฉพาะกับ bot (cloaking)
- [ ] เขียนตัวเลขราคา/ประหยัดที่ไม่มีหลักฐาน → เสียความน่าเชื่อถือ ไม่ใช่แค่เสีย SEO

## Part 12: ลำดับการทำงาน

### ระยะ 0: ปลดล็อกการวัด (สัปดาห์ที่ 1)
เชื่อม GSC + GA4 → ไม่มีขั้นนี้ ทุกอย่างหลังจากนี้วัดไม่ได้

### ระยะ 1: ข้อมูลเฉพาะจังหวัด P1 (เดือนที่ 1-2)
5 จังหวัด: กรุงเทพ, ชลบุรี, ปทุมธานี, นครราชสีมา, พิษณุโลก
ต่อจังหวัดต้องมี: PEA/MEA (มีแหล่งอ้างอิง), อำเภอ, ข้อมูลแสงแดด (PVGIS), ขั้นตอนอนุญาต
**ข้อมูลแสงแดดทำเสร็จแล้วครบ 77/77 จังหวัด** เหลืออำเภอกับ PEA/MEA
เป้าหมาย: ลดความซ้ำจาก 0.829 ให้เหลือต่ำกว่า 0.6 ในกลุ่มนี้

### ระยะ 2: เปิด static shell (เดือนที่ 2-3)
ทำเมื่อระยะ 1 เสร็จ เพราะ shell ต้องมีเนื้อหาเฉพาะจังหวัด
ตรวจ robots.txt ของ AI crawler ในระยะเดียวกัน

### ระยะ 3: ขยาย 77 จังหวัด (เดือนที่ 3-6)
ทำทีละกลุ่ม วัดความซ้ำทุกครั้ง ถ้าความซ้ำไม่ลด = หยุดและหาสาเหตุก่อนขยายต่อ

### ระยะ 4: cluster pages (เดือนที่ 4-6)
เฉพาะจังหวัดที่มีข้อมูลพร้อม เริ่มจาก factory/hotel เพราะ L2 map ชี้ไปที่นี่

### ระยะ 5: authority (ต่อเนื่อง)
case study จากการติดตั้งจริง → รีวิว → earned media

## Part 13: สิ่งที่ผมทำไม่ได้

| สิ่งที่ขอ | เหตุผล |
| --- | --- |
| รายชื่อคีย์เวิร์ดที่ขึ้น Google Trends | ไม่มี Trends API, ไม่มี GSC |
| ปริมาณค้นหาและ difficulty | ไม่มีเครื่องมือวัด |
| การันดับ | ขึ้นกับคู่แข่งและอัลกอริทึม รับประกันไม่ได้ |
| backlink profile วิเคราะห์ | ไม่มี Ahrefs/Majestic |
| การสร้าง backlink | ต้องได้จากเว็บอื่น ทำแทนไม่ได้ |
| ตัวเลขราคา/ประหยัด/รับประกัน | ไม่มีหลักฐาน |
| เนื้อหา 12,000 คำ × 77 จังหวัด | ผิดนิยาม scaled content abuse |

## แหล่งอ้างอิง

1. Google Search Central, "Spam policies for Google web search",
   `https://developers.google.com/search/docs/essentials/spam-policies`
   (อ่านเมื่อ 2026-09-26, หน้าแก้ไขล่าสุด 2026-08-28)
   ใช้สำหรับนิยาม doorway abuse, scaled content abuse, keyword stuffing, link spam,
   qualified outbound links, site reputation policy
2. ผลตรวจของตัวเองบน `www.sirinx.co` และ local production build (ดูรายละเอียดใน
   `docs/SEO_AEO_AUDIT_20260925.md`)
3. ข้อมูลเชิงปฏิบัติส่วนอื่นใน Part 6-9 ระบุเป็นข้อเสนอแนะ ไม่ได้อ้างแหล่งทางการ
   ควรตรวจสอบกับแหล่งทางการก่อนใช้ตัดสินใจลงทุน
4. PVGIS v5.3 (European Commission JRC), `https://re.jrc.ec.europa.eu/pvg_tools/en/tools.html`
   ฐานข้อมูล PVGIS-ERA5 ช่วงปี 2005-2023 ดึงเมื่อ 2026-09-26
   ใช้สำหรับค่าการแผ่รังสีรวมเฉลี่ยและผลผลิตต่อหน่วยกำลังของครบ 77 จังหวัด
5. พิกัดจังหวัดจาก th.wikipedia.org (บทความจังหวัดแต่ละจังหวัด)
6. การไฟฟ้านครหลวง, `https://www.mea.or.th/` และการไฟฟ้าส่วนภูมิภาค, `https://www.pea.co.th/`
   **ยังไม่ได้ดึงข้อมูลเขตพื้นที่จากสองแหล่งนี้** หน้าเว็บทั้งสองเป็น JS-driven
   จึงยังยืนยัน PEA/MEA รายจังหวัดไม่ได้ และไม่ได้เขียนลงหน้าใด
